# UX Findings (pre-redesign audit)

## Screen inventory

- NotesPage (lib/features/home/notes_page.dart) — Tab 0 of MemShell. Paginated timeline of all Mem notes grouped by last-updated day (local time), fetched via rawListNotes(limit 40, includeContent false, opaque page cursor). Top: horizontal collection-filter ChoiceChip bar ('All' + one chip per collection, capped at 100) on a tinted band, with a collections-manage icon that swaps to a spinner while loading. Rows are flat cards: article icon, title, 2-line snippet, jm-format updated time; tap pushes NoteDetailPage(noteId). Pull-to-refresh reloads collections + notes; a manual 'Load more' TextButton paginates. Refreshes externally via AppState.notesListRevision. States: hydration spinner, 'Add your Mem API key' message, raw-error text, dual loading indicators; no true empty state.
- CollectionsManagePage (lib/features/home/collections_manage_page.dart) — Full-screen CRUD for collections, pushed from NotesPage (which reloads on pop). ListView of card rows (folder icon, title, description OR '<n> notes' subtitle — never both) with a kebab menu (Edit/Delete); row tap does nothing. FAB opens a create/edit bottom sheet (_CollectionEditorSheet: title + optional description + Save); delete uses a confirm AlertDialog. Every successful mutation bumps notesListRevision so the Notes tab stays in sync. Loading is a spinner 120px from top; errors are raw e.toString(); no empty state.
- CapturePage (lib/features/capture/capture_page.dart) — Tab 1 of MemShell; fast-capture lane kept alive by IndexedStack (drafts and in-progress recordings survive tab switches). One flat ListView stacking: mic-mode SegmentedButton (Longform vs Hold-to-talk), a 180px circular record button with level meter and elapsed time, transcription config (replace/append switch, auto-punctuation switch, language mode + hint field, Whisper prompt field), the Content TextField (8-16 lines), an Instructions field, then two CTAs below the fold: 'Mem-it (smart capture)' (server-side processing via memIt) and 'Save as raw markdown note' (createNote). Voice pipeline records AAC-LC to a temp file, transcribes via OpenAI Whisper (key resolved: voice key → active openai chat model → first openai model), inserts transcript into Content. Successful saves silently clear fields and bump notesListRevision; errors are raw-exception snackbars.
- MemChatPage (lib/features/chat/mem_chat_page.dart) — Tab 2 of MemShell. flutter_chat_ui conversation with a Mem-tool-enabled LLM agent (openai/anthropic/gemini dispatch on literal provider strings), themed with library ChatTheme.dark() that clashes with the app theme. AppBar title doubles as model indicator ('<displayName> (<provider>)' or 'No model'). A permanent 52px 'Jobs' strip shows up to 12 prompt-template ActionChips plus an 'All' chip opening a searchable picker sheet; tapping runs the prompt immediately. Sessions persist per model profile (ChatSessionStore, 5-day retention); switching the active model silently swaps the whole conversation. Consumes ChatPromptQueue jobs from the home widget (serial FIFO, polls while busy, fires completion notifications). Streaming rewrites a '…' placeholder bubble; errors render as 'Error: '-prefixed bubbles and get persisted; empty state is a blank void.
- ChatPromptQueue (lib/features/chat/chat_prompt_queue.dart) — Non-visual ChangeNotifier FIFO bridging MemShell (producer: memai://prompt?templateId deep links from the Android home widget) and MemChatPage (consumer). enqueue() adds + notifies; drainAll() atomically copy-and-clears. One shared instance created by MemShell and injected into MemChatPage. Nothing visual to redesign, but its consumer currently gives zero queue/running feedback and there is no dedupe or cancel.
- NoteDetailPage (lib/features/note/note_detail_page.dart) — Full-screen single-note view pushed with noteId. Read mode: selectable MarkdownBody (deliberately not the Markdown widget) plus non-interactive collection chips. Edit mode: raw markdown TextField (first line = title, a Mem API semantic) with FilterChips for collection assignment; Save does one combined updateNote(markdown + collectionIds + version) with optimistic concurrency, repopulating state from the server response. AppBar is a state machine on inTrash/_editing: Edit/Trash icons, Save/Cancel text buttons, Restore, and an always-present one-item overflow ('Delete permanently…'). Trash/restore keep the user on the page and reload; hard delete pops. All mutations bump notesListRevision. No unsaved-changes guard, no metadata shown, no trashed-state banner, raw-exception errors.
- SettingsPage (lib/features/settings/settings_page.dart) — Pushed via the gear on every primary tab. One flat ListView of six prose-heavy sections: Mem REST API key (explicit Save button; empty input deletes the key), MCP OAuth connect/disconnect (status = plain ListTile string + disabled-button state), chat model profiles (RadioListTile cards with kebab Edit/Remove, add/edit via a cramped AlertDialog with provider/model dropdowns + key field, keys in SecureVault keyed by profile id), voice transcription (Whisper model dropdown 'whisper-1'/'gpt-4o-mini-transcribe' + OpenAI key field), a 'Manage prompt jobs' navigation ListTile to PromptJobsPage, and a static security paragraph. Secrets prefill into obscured-but-revealable TextFields; feedback is snackbar-only.
- PromptJobsPage (lib/features/settings/prompt_jobs_page.dart) — Pushed from Settings. Manages reusable prompt-job templates: 'Add widget to home' button (gated on isPinWidgetSupported, sync-before-pin ordering), a 'Pinned for widget (n/4)' ReorderableListView (order source of truth = pinnedTemplateIds; drag handle icon is decorative), and an 'All jobs' card list with kebab Edit/Pin-Unpin/Delete. FAB opens a create/edit bottom sheet (title + prompt body; silent no-op on empty input). Template ids are stable contract for home-widget deep links (memai://prompt?templateId=<id>) and widget sync.
- settingsIconActions (lib/widgets/settings_launcher.dart) — Tiny shared helper returning the AppBar actions list with a settings gear IconButton (no tooltip, no state/badging) that pushes const SettingsPage() over the shell's NavigationBar. Consumed by all three tab AppBars; the redesign's shared settings entry point.

## Shared patterns to extract

- Card surface: Material(color: Theme.cardTheme.color #121212, BorderRadius.circular(14)) is hand-rolled in Notes rows, Collections rows, PromptJobs tiles, and Settings model cards — always flat on #050505 with no border/elevation, and radius 14 clashes with the theme's 16. Extract one AppCard/AppListRow component with a single radius, surface treatment, and OLED-friendly separation.
- Tinted horizontal chip strip: surfaceContainerHighest @ 35% alpha band with a horizontally scrolling chip row appears twice (Notes collection-filter bar, Chat 52px Jobs strip), both with ad-hoc paddings, no edge fade/scroll hint, and sub-48dp chip targets (Chat's top:10 hack). Extract a shared ChipStrip with proper touch targets, overflow affordance, and optional pinning.
- Modal editor bottom sheet: Collections editor, Prompt-job editor, and the Jobs picker all use showModalBottomSheet(isScrollControlled, showDragHandle) + Padding(L/R 20, top 8, bottom viewInsets+20) + titleMedium header + trimmed TextFields + full-width FilledButton Save with an 18x18 inline spinner, silent no-op on empty input, no Cancel control, and the capture-messenger-then-pop-then-callback save ordering. Extract one EditorSheet scaffold with real validation, a close affordance, and the keyboard-avoidance contract baked in.
- Error surfaces: every screen renders failures as raw e.toString() — full-screen centered text (Notes, Collections, NoteDetail) or snackbars (Capture, Chat, Settings) — with no icon, retry, or human copy; MemApiClient.formatError exists but is unused. Build one ErrorState component (message + retry) and one error-snackbar helper that route through formatError.
- Empty states: none exist anywhere (Notes zero-notes, Collections, Chat fresh conversation, Chat models section, All-jobs list, empty note body). Build a shared EmptyState (icon + copy + CTA) — several CTAs can use goToShellTab / Navigator to Settings.
- Destructive confirm dialog: trash note, delete note forever, delete collection, and remove model all use showDialog<bool> AlertDialogs whose destructive action is a primary-colored FilledButton with no error styling and no undo. Extract one ConfirmDestructiveDialog (error-colored action, resolves bool, outside-tap = no-op) reused everywhere.
- Row + kebab PopupMenuButton: Collections rows, Prompt-job tiles, and Settings model cards all hide primary actions behind a three-dot menu while the row itself is inert or cramped. Standardize a list-row component with a visible primary action and consistent overflow.
- Section header + prose blurb: bare titleMedium/titleSmall Text plus a bodySmall.copyWith(onSurfaceVariant) paragraph is duplicated ~10x across Settings, PromptJobs, Capture, and NoteDetail. Extract SectionHeader/SectionDescription tokens and cut the prose.
- Inline OutlineInputBorder(): re-declared on every TextField in Capture, Settings, both editor sheets, NoteDetail, and the jobs picker. Move to a global InputDecorationTheme.
- Inline spinner sizes: 18x18 and 20x20 CircularProgressIndicator(strokeWidth: 2) hardcoded in buttons and bars across five files. One ButtonSpinner/InlineSpinner token.
- Snackbar-only feedback with inconsistent copy ('Saved.', 'Collection created.', 'Job saved.', 'Changes saved.'): standardize a feedback helper with a copy system and optional undo action.
- Pull-to-refresh contract: RefreshIndicator + AlwaysScrollableScrollPhysics on every list state (including error/empty branches) in Notes and Collections — keep as a shared list-scaffold behavior.
- Magic bottom insets to clear chrome: SliverPadding(bottom:120) for the NavigationBar (Notes), ListView bottom 96 for the FAB (PromptJobs), bottom 12 with FAB occlusion bug (Collections). Centralize safe-area/chrome insets.
- Disabled-buttons-as-status: MCP Connect/Disconnect pair and the 'Add widget to home' button communicate state purely by which button is greyed out. Replace with an explicit status component (icon + label + single action).
- Settings gear via settingsIconActions on all three tab AppBars — keep as the shared entry point but upgrade to a proper widget with tooltip/Semantics and a setup-needed badge driven by hasMemRest / chatModels / mcpConnected.
- Post-frame AppScope access + mounted-guard-after-every-await + capture-ScaffoldMessenger-before-await: the same async hygiene pattern is hand-copied in every screen; a shared mixin/helper would prevent regressions during the redesign.

## Top UX problems (ranked)

- 1. Raw exceptions as user-facing copy, with no recovery path: every screen surfaces e.toString() ('Exception: DioException…') in full-screen error states and snackbars, none offer a retry button, and some failures are silently swallowed (collection loads on Notes and NoteDetail) leaving stale UI with no signal. MemApiClient.formatError exists and is unused.
- 2. Silent data-loss traps: NoteDetail has no unsaved-changes guard (system back or Cancel discards edits instantly), Capture clears all fields on success with zero confirmation (reads as loss) and has no undo, switching the active chat model silently swaps the entire visible conversation, and switching mic mode mid-recording discards audio without confirmation.
- 3. No empty states or first-run guidance anywhere: fresh Notes list, Collections, Chat, chat-models section, and jobs list are all blank voids; missing-key/missing-model states are discovered reactively via snackbar after a failed tap; the settings gear carries no badge even though the app is unusable until configured; no snackbar offers an 'Open Settings' action.
- 4. Loading/progress feedback is broken or misleading: Notes blanks the whole list to a spinner on every refresh and filter change (no stale-content retention, no skeletons, dual indicators on first load); Chat's pending state is a static '…' bubble with timestamp churn; Capture's save buttons just grey out with no spinner; Settings' OAuth connect gives no feedback during the browser round-trip.
- 5. Destructive-action grammar is wrong app-wide: every destructive confirm (trash, delete forever, delete collection, remove model) styles the dangerous action as the promoted primary FilledButton, no deletion offers undo, 'Delete permanently…' lives in an always-visible single-item overflow menu, and MCP Disconnect has no confirm at all.
- 6. Primary actions buried or hostile: Capture's two save CTAs sit below ~6 config controls and get covered by the keyboard; advanced Whisper config clutters every visit instead of living behind a disclosure; Notes uses a small manual 'Load more' button above 120px of dead space instead of infinite scroll; pinning jobs is hidden in a kebab menu; editing a collection takes two taps while tapping the row does nothing.
- 7. No search anywhere despite a dedicated searchNotes API — Notes, Collections, and Settings are all scroll-only; the jobs list has no search/sort once it grows.
- 8. Touch-target and input-timing failures: Chat job chips are ~32px tall (under the 48dp minimum) and vertically off-center; push-to-talk starts recording only after the ~500ms long-press timeout, clipping the first half-second of speech, with no pressed-vs-recording distinction and no slide-to-cancel; the collections FAB can occlude the last row's menu; NoteDetail's tall TextField has no scroll-to-cursor handling.
- 9. Chat tab breaks the design language: library ChatTheme.dark() bubbles/input bar don't match the blue-seeded M3 theme, surface #0A0A0A seams against scaffold #050505, the AppBar title is a debug-ish model string with no tap affordance or in-place switcher, errors persist into history as fake assistant replies, and there is no stop/cancel for in-flight generation (busy sends are scolded via snackbar).
- 10. False affordances: read-mode collection chips look tappable but do nothing, collection rows look tappable but do nothing, the drag_handle icon on pinned jobs is decorative (real gesture is long-press anywhere), and the voice level meter is a LinearProgressIndicator that reads as a loading bar and stays primary-colored while recording.
- 11. Information starvation on rows: every note shows the identical article icon with no collection tags/colors, filter chips have no note counts, collection rows show description OR count (never both, unpluralized), NoteDetail surfaces zero metadata (no timestamps, no trashed-state banner), and job tiles show no pinned indicator in the All list.
- 12. Settings is a README, not a settings screen: six sections separated only by bare headers and prose paragraphs, explicit Save buttons with no dirty-state tracking, secrets revealable in plaintext behind the eye toggle, MCP status conveyed by which button is disabled, and the model editor is a cramped stacked AlertDialog.
- 13. Invisible background work: home-widget prompt jobs run with no in-chat 'running <title>' indicator, queued jobs stack invisibly (double-tapping the widget burns two LLM runs with no dedupe), and memIt's async request_id is never surfaced as a processing status.
- 14. Jargon and inconsistent vocabulary: 'Mem-it (smart capture)', 'Transcription insertion mode', 'Whisper prompt hint', 'Jobs' vs 'prompt templates' vs 'prompt jobs', raw redirect URLs and API model ids exposed in copy.
- 15. Non-standard interactions: chat long-press silently copies to clipboard instead of a context menu, date group headers are verbose ALL-CAPS absolute dates with no Today/Yesterday, group ordering can break with mixed server ordering, and no transition polish (no hero/shared-element into NoteDetail, default routes everywhere).

## Unused data / API opportunities

- searchNotes({query, limit, offset, snapshotId}) — a full search endpoint (POST /v2/notes/search) with its own pagination scheme is completely unused; no search UI exists anywhere in the app.
- MemNoteListItem.collectionIds — every list row already carries its collection memberships, but note cards show a generic article icon instead of collection chips/tags (requires a client-side id→title join against the collections list, which Notes already fetches).
- MemNoteListItem.createdAt — only updatedAt is shown, unlabeled; created-vs-updated distinction and relative timestamps (Today/Yesterday) are available for free.
- MemCollectionItem.noteCount — only shown as a fallback subtitle when a collection has no description (and unpluralized); never shown on the Notes filter chips, where per-chip counts are the obvious upgrade. description and noteCount could both be shown together.
- MemCollectionItem.createdAt/updatedAt — never surfaced in the collections manager (no 'updated 2d ago' metadata, no sort options).
- MemNoteFull.createdAt/updatedAt — NoteDetail shows zero metadata between the app bar and body; MemNoteFull.trashedAt is only implied by button swaps instead of an explicit trashed banner; word/character count is derivable from content.
- MemApiClient.formatError(DioException) — purpose-built human-readable error extraction, never called; every error surface uses e.toString() instead.
- createNote({collectionIds?, collectionTitles?}) — Capture cannot assign a collection at save time even though the API supports attach-by-id and auto-create-by-title.
- memIt returns a request_id (and accepts a context param) — the UI treats it as fire-and-forget with no processing indicator; trash/restore/deleteNoteHard also return request_ids that could inform eventual-consistency messaging (the list may not reflect the change immediately after a refresh).
- readCollection(collectionId) — unused; could power a collection detail/landing view (read-mode collection chips on NoteDetail currently do nothing and could deep-link to a filtered Notes view via existing filter state instead).
- listNotes includeContent=true — never requested; richer previews are possible where snippet is null (snippet is nullable and often absent).
- ChatSessionSnapshot.savedAt + 5-day retention — restored conversations appear with no 'restored from <date>' indicator or retention hint; ChatPromptQueue.hasPending is exposed but never used to show queue state in the chat UI.
- chatProviderBrand(provider) from curated_chat_models.dart — provider branding exists in code but the UI shows raw strings like '(openai)' in the AppBar and raw API model ids as subtitles in Settings.
- Collection color/emoji does NOT exist in the data model — a redesign wanting colored collection chips must derive color client-side (e.g. stable hash of collection id); flag this to DESIGN as a derived token, not an API field.
- rawListNotes next_page cursor — already parsed by NotesPage, but the typed listNotes drops it; an infinite-scroll redesign should keep using rawListNotes (or extend the client) rather than the typed method.
- AppState.goToShellTab / shellTabRequest — an existing cross-tab navigation channel that empty-state CTAs (e.g. 'Capture your first note' from an empty Notes list) can use for free.
